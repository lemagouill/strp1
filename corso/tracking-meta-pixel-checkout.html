Configurer le Meta Pixel sur votre checkout personnalisé

5 min·Technique

Suivez chaque conversion avec le Meta Pixel sur votre checkout Corsopay. Configuration server-side en 2 clics.

Vous depensez 500, 1 000, 5 000 euros par mois en publicite Meta (Facebook/Instagram). Mais savez-vous combien de conversions votre checkout genere reellement ? Si vous utilisez un checkout externe ou personnalise, il y a de fortes chances que votre Meta Pixel ne capte qu'une partie des conversions. Et des donnees incompletes = des campagnes mal optimisees = de l'argent gaspille.

Ce guide vous explique comment configurer le Meta Pixel (et le TikTok Pixel) sur votre checkout personnalise Corsopay. On va couvrir la difference entre tracking client-side et server-side, pourquoi c'est critique en 2026, et comment tout mettre en place en moins de 2 minutes.

Pourquoi le tracking de conversion est vital

Le Meta Pixel est le cerveau de vos campagnes publicitaires. Il envoie des signaux a l'algorithme Meta pour lui dire : "Ce type de personne a achete. Trouve-moi d'autres personnes similaires." Plus le Pixel recoit de signaux de conversion, plus l'algorithme s'affine, et plus votre ROAS (Return On Ad Spend) s'ameliore.

Sans tracking precis, voici ce qui se passe :

  • L'algorithme tourne en aveugle : il ne sait pas qui achete, donc il ne peut pas optimiser vos campagnes
  • Votre CPA (cout par acquisition) explose: sans signaux de conversion, Meta cible n'importe qui au lieu de vos clients ideaux
  • Vos audiences Lookalike sont inefficaces : elles sont basees sur des donnees incompletes ou erronees
  • Vous ne pouvez pas calculer votre ROI reel : impossible de savoir quelle campagne, quel ad set, quelle creative genere des ventes
"Le jour ou on a corrige notre tracking, on a decouvert que notre campagne la plus rentable n'etait pas celle qu'on pensait. On depensait 60% de notre budget sur la mauvaise audience." — E-commercant Shopify, 25K/mois en pub Meta

Tracking client-side vs server-side : la difference cruciale

Il existe deux facons de tracker les conversions. Comprendre la difference est essentiel pour ne pas perdre de donnees.

Le tracking client-side (navigateur)

C'est le tracking classique. Un script JavaScript (le Meta Pixel) est charge dans le navigateur du client. Quand le client finalise un achat, le script envoie un evenement "Purchase" a Meta.

Le probleme : en 2026, ce tracking est de moins en moins fiable. Voici pourquoi :

  • Bloqueurs de pubs : 42% des internautes utilisent un bloqueur qui empeche le Pixel de se charger
  • iOS 14.5+ : Apple demande le consentement pour le tracking. 85% des utilisateurs refusent. Le Pixel ne peut plus les suivre
  • Navigateurs restrictifs : Safari, Firefox et Brave bloquent de plus en plus les cookies tiers
  • RGPD / Consentement : les bannieres cookies qui permettent de refuser le tracking reduisent encore la couverture

Resultat : le tracking client-side ne capte souvent que 50 a 60% des conversions reelles. Vous prenez des decisions basees sur des donnees incompletes.

Le tracking server-side (API Conversions)

Le tracking server-side fonctionne differemment. Au lieu d'envoyer les evenements depuis le navigateur du client, ils sont envoyes directement depuis le serveur de votre checkout vers les serveurs de Meta (via l'API Conversions).

Les avantages sont enormes :

  • Insensible aux bloqueurs de pubs: le signal est envoye depuis le serveur, pas depuis le navigateur. Les bloqueurs ne peuvent pas l'intercepter
  • Insensible aux restrictions iOS: meme si l'utilisateur a refuse le tracking iOS, le serveur peut envoyer l'evenement de conversion
  • Donnees plus fiables : le serveur a acces a toutes les informations de la transaction (email, montant, produits) sans dependre des cookies
  • Deduplication intelligente : Meta deduplique automatiquement les evenements envoyes en client-side et server-side pour eviter les doublons

Pro tip : Le tracking server-side capture en moyenne 20 a 40% de conversions en plus par rapport au tracking client-side seul. Pour un e-commercant qui depense 3 000 euros/mois en pub Meta, ca peut representer la difference entre un ROAS de 2x et un ROAS de 3.5x.

Comment Corsopay gere le tracking

Corsopay integre nativement le tracking server-side via l'API Conversions de Meta. Concretement, voici ce qui se passe quand un client finalise un achat sur votre checkout :

  • Evenement InitiateCheckout : envoye quand le client arrive sur la page de checkout
  • Evenement AddPaymentInfo : envoye quand le client entre ses informations de paiement
  • Evenement Purchase : envoye quand le paiement est confirme, avec le montant exact, la devise, et les identifiants produits

Chaque evenement est envoye en server-side (via l'API Conversions) ET en client-side (via le Pixel dans le navigateur). Meta deduplique automatiquement pour ne compter chaque conversion qu'une seule fois. Vous obtenez ainsi la meilleure couverture possible.

Les donnees envoyees avec chaque evenement incluent :

  • Email du client (hashe en SHA-256 avant l'envoi)
  • Montant de la transaction
  • Devise (EUR, USD, etc.)
  • ID des produits (pour le matching avec votre catalogue)
  • Adresse IP et User-Agent (pour le matching d'audience)

Configurer mon tracking

Guide : configurer le Meta Pixel sur Corsopay

La configuration prend litteralement 2 minutes. Voici les etapes :

1. Recuperer votre Pixel ID

Connectez-vous a votre Meta Business Suite (business.facebook.com). Allez dans Evenements → Sources de donnees. Cliquez sur votre Pixel. L'ID du Pixel est un nombre a 15-16 chiffres affiche en haut de la page (ex: 1234567890123456).

Si vous n'avez pas encore de Pixel, cliquez sur "Ajouter une source de donnees" → "Web" → "Meta Pixel" pour en creer un. Nommez-le avec le nom de votre boutique.

2. Recuperer votre Access Token (API Conversions)

Toujours dans la page de votre Pixel, cliquez sur l'onglet "Parametres ". Scrollez jusqu'a "API Conversions". Cliquez sur "Generer un token d'acces". Copiez ce token — il est necessaire pour le tracking server-side.

3. Coller dans le dashboard Corsopay

Dans votre dashboard Corsopay, allez dans "Parametres" →"Tracking". Vous verrez deux champs :

  • Meta Pixel ID : collez votre ID Pixel (15-16 chiffres)
  • Meta Access Token : collez le token genere a l'etape precedente

Cliquez sur "Enregistrer". C'est fait. Le tracking server-side est immediatement actif.

4. Verifier que ca fonctionne

Pour verifier que votre Pixel fonctionne correctement :

  • Installez l'extension Chrome Meta Pixel Helper — elle affiche en temps reel les evenements envoyes par le Pixel
  • Allez sur votre checkout Corsopay et verifiez que l'evenement InitiateCheckouts'affiche
  • Faites un achat test et verifiez que l'evenement Purchaseapparait avec le bon montant
  • Dans Meta Business Suite → Evenements → Test des evenements, verifiez que les evenements server-side apparaissent avec le label "Serveur"

Pro tip :Dans Meta Business Suite, l'outil "Test des evenements" vous permet de voir les evenements en temps reel pendant 24h. Utilisez-le juste apres la configuration pour confirmer que tout fonctionne. Si vous voyez des evenements avec le label "Navigateur" ET "Serveur", c'est parfait — le double tracking est en place.

Bonus : configurer le TikTok Pixel

Si vous faites de la pub TikTok, Corsopay supporte egalement le TikTok Pixel avec l'Events API (l'equivalent server-side de TikTok). La configuration est identique :

  • Recuperez votre TikTok Pixel ID dans TikTok Ads Manager → Evenements → Gestion du pixel web
  • Generez un Access Tokenpour l'Events API
  • Collez les deux dans le dashboard Corsopay, section "Tracking"→ "TikTok"

Les evenements envoyes sont les memes : InitiateCheckout, AddPaymentInfo, Purchase. Le format est adapte automatiquement au schema TikTok. Vous n'avez rien a configurer cote technique.

Pourquoi le server-side est encore plus important sur TikTok

L'audience TikTok est majoritairement mobile (92%). Et sur mobile, les restrictions de tracking sont maximales : iOS bloque le Pixel, les navigateurs in-app ont des limitations, et les bloqueurs de pubs sont courants. Le tracking server-side est donc encore plus critique pour TikTok que pour Meta. Sans lui, vous perdez potentiellement 50 a 70% de vos signaux de conversion.

  • Reporting fiable : les chiffres dans Meta Ads Manager refletent enfin la realite de vos ventes

FAQ

Est-ce que le tracking server-side est conforme au RGPD ?

Oui. Les donnees personnelles (email, adresse IP) sont hashees en SHA-256 avant d'etre envoyees a Meta ou TikTok. Corsopay ne stocke aucune donnee personnelle sur ses serveurs. Le tracking respecte les directives CNIL et RGPD.

Est-ce qu'il y aura des doublons dans mes evenements ?

Non. Corsopay utilise un event_idunique pour chaque evenement, envoye en client-side et server-side. Meta et TikTok utilisent cet ID pour dedupliquer automatiquement. Chaque conversion n'est comptee qu'une seule fois.

Est-ce compatible avec mon Pixel existant sur Shopify ?

Oui. Le Pixel Corsopay track les evenements du checkout (InitiateCheckout, Purchase). Votre Pixel Shopify continue de tracker les evenements de navigation (ViewContent, AddToCart). Les deux fonctionnent en parallele sans conflit.
